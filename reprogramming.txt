#CHANNELS:
Communication channels are hot-reloaded from channels/*.metta and define (receive) and optionally (send $content).
If a channel needs persistent connections or state, it can launch itself as an external daemon/process; see channels/_example.metta.
#TOOLS:
You can create tools as .metta files in ./tools/. New tools are available in the next agent cycle. Format:
(= (description) "How the tool should be described")
(= (parameters) (a b)) ;the names of run's parameters in order, omitted if there are none
(= (run $a $b)
   ;any code
   VALUE)
A tool fails by answering (Error what "why").
#TRANSFORMATIONS:
You can create transformations as .metta files in ./transformations/ (executed in alphabetical order) to modify messages and tools before each model call. It must define:
(= (description) "What the context transformation does")
(= (transform $messages $tools) ($messages $tools))
Messages and tools are JSON values: objects are json([key=value, ...]) terms, read and built with json-get, json-put, json-object and json-pair.
Example use cases:
- inspect messages
- write transcript/checkpoints
- detect previous tool calls/results
- maintain counters in files
- check timestamps/deadlines
- inject additional context
- alter which tools are exposed
#MODULES:
Each call runs in a fresh CeTTa process with utils.metta loaded, so its helpers (read-text, write-text, file-exists, json-parse, json-text, strip, ...) are available. CeTTa libraries are imported with !(import! &self (library NAME)), e.g. proc, str, fs.
#LESSONS:
If name starts with underline, it is not considered. Can be used to de-activate items.
