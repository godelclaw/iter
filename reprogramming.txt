#CHANNELS:
Communication channels are hot-reloaded from channels/*.metta and define (receive) and optionally (send $content).
If a channel needs persistent connections or state, it can launch itself as an external daemon/process; see channels/_example.metta.
channels/irc.metta is a native TCP/TLS example with locked retry/activity state and atomic spools. Its pending/uncertain/written files distinguish queued requests from uncertain effects and completed local writes, never server delivery; uncertain originals must not be replayed automatically. See README.md for its configuration and local qualification boundaries.
#TOOLS:
You can create tools as .metta files in ./tools/. New tools are available in the next agent cycle. Format:
(= (description) "How the tool should be described")
(= (parameters) (a b)) ;the names of run's parameters in order, omitted if there are none
(= (run $a $b)
   ;any code
   VALUE)
A tool fails by answering (Error what "why").
#TRANSFORMATIONS:
You can create transformations as .metta files in ./transformations/ (executed in alphabetical order) to modify messages and tools before each model call. It must define:
(= (description) "What the context transformation does")
(= (transform $messages $tools) ($messages $tools))
Messages and tools are CeTTa JSON values: each is a (JsonArray (...)) of objects (JsonObject ((JsonPair "key" value) ...)), whose values are strings, numbers, true, false, JsonNull, objects and arrays. (json:get $object "key") reads a value.
Example use cases:
- inspect messages
- write transcript/checkpoints
- detect previous tool calls/results
- maintain counters in files
- check timestamps/deadlines
- inject additional context
- alter which tools are exposed
#MODULES:
Each call runs in a fresh CeTTa process with utils.metta loaded, so its helpers (str-cat, text, ...) and CeTTa's json, str, fs, system, proc and io libraries are available: call json:parse, fs:read-text, fs:write, str:trim, ... directly. Other libraries are imported with !(import! &self (library NAME)).
A process that a module starts with proc:run should have the option (lifetime owner), so that it ends with the call.
#PYTHON MODULES:
A tool, channel or transformation may instead be a .py file in the same folder, in the format of Python Iter: a tool defines DESCRIPTION = "..." and run(a, b); a channel defines receive() and optionally send(content); a transformation defines DESCRIPTION and transform(messages, tools), whose messages and tools are lists and dicts and which returns (messages, tools). A Python module runs in the call's own Python. Raising an exception fails the call. The python tool exposes both Python and MeTTa tools as callables. Native tools run in the Iter workspace even if the Python snippet changes its own working directory.
#LESSONS:
If name starts with underline, it is not considered. Can be used to de-activate items.
If the same module has both .metta and .py files, the .metta module wins. It is never run twice.
